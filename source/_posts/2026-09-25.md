# Rust `no_std` 编程

## Rust 程序的启动链路

首先来看一段我们已经很熟悉的代码

```rust
fn main() {
    println!("Hello, World!");
}
```

在常规 Rust 语言的学习中, 我们知道程序从 `main` 函数开始. 一般情况下, Rust 的 `main` 函数是没有返回值的, 或者说返回一个单元类型, 但有些时候, `main` 也可以返回一个 `Result` 类型. 如果有 C 语言的基础, `int main()` 这个函数前面实际上也暗示了, `main` 函数是有返回值的. 那么, 谁接收了这个返回值? 为什么 0 代表成功, 其他值代表出现了错误? 如此一来就会发现, `main` 的背后必定存在一个更早启动, 更晚退出, 负责程序的初始化与收尾的 **隐型函数**

> 这里先补一句严谨的说法. `main` 并不是"没有返回值", 它默认返回 `()`. Rust 对 `main` 的规则是: 无参数, 且返回类型必须实现 `Termination` 这个 `#[lang]` 项. 实现它的类型有 `()`, `!`, `ExitCode`, 以及 `Result<T, E> where E: Debug`. `Termination::report()` 把返回值折成 `ExitCode`: `()` 与 `ExitCode::SUCCESS` 得到 0, `ExitCode::FAILURE` 与 `Err(_)` 得到 1 (后者还会往 stderr 打印 `Error: {err:?}`, 所以 `E` 必须满足 `Debug`). 而 `panic!` 得到的是 101. 这个数字不是语言规范, 是 std 运行时的实现细节

那么这层薄封装是什么? 以 **x86_64-unknown-linux-gnu** 为例, 这个隐型函数就是 `libc` 提供的 `__libc_start_main`, 这里不做展开

下面给出 **简化过的伪代码**, 与真实实现不同, 但基本流程差不多, 简单展示一下上面的 Rust 代码展开后的完整状态

```rust
// 这段代码无法编译

// ===== 内核跳转到 ELF 入口点 =====
#[unsafe(no_mangle)]
pub unsafe extern "C" fn _start() -> ! {
    // 栈顶是内核压入的 argc/argv/envp
    let argc: isize = read_argc_from_stack();
    let argv: *const *const u8 = read_argv_from_stack();

    // 把 main 的地址和参数交给 libc
    __libc_start_main(main, argc, argv, init, fini, rtld_fini, stack_end);
}

// ===== libc 提供 =====
unsafe fn __libc_start_main(
    main_fn: extern "C" fn(i32, *const *const u8, *const *const u8) -> i32,
    argc: isize,
    argv: *const *const u8,
    init: extern "C" fn(),
    fini: extern "C" fn(),
    rtld_fini: extern "C" fn(),
    stack_end: *mut core::ffi::c_void,
) -> ! {
    init_libc();   // TLS, canary, .init_array, 线程支持...
    let ret = main_fn(argc, argv, envp);
    exit(ret);
}

// ===== Rust 编译器生成 (codegen 直接声明, 不是源码里的 item) =====
#[unsafe(no_mangle)]
pub extern "C" fn main(argc: i32, argv: *const *const u8) -> i32 {
    // 注意: 它不直接调用用户的 main, 而是把函数指针交给 lang_start
    lang_start(user_main, argc, argv, sigpipe) as i32
}

// ===== Rust std 提供 =====
fn lang_start<T: Termination + 'static>(
    user_main: fn() -> T,
    argc: isize,
    argv: *const *const u8,
    sigpipe: u8,
) -> isize {
    lang_start_internal(&move || user_main().report().to_i32(), argc, argv, sigpipe)
}

fn lang_start_internal(
    main: &(dyn Fn() -> i32 + Sync + RefUnwindSafe),
    argc: isize,
    argv: *const *const u8,
    sigpipe: u8,
) -> isize {
    let exit_code = catch_unwind(main);
    cleanup();
    exit_code.unwrap_or(101)
}

// ===== 用户代码 =====
fn user_main() {
    println!("Hello, World!");
}
```

为什么 Rust 需要这层封装? 因为 Rust 的标准库 `std` 承诺了一些 **程序级** 的语义, 这些语义必须在 main 之外维护, 例如

- `panic` 的捕获与报告: `lang_start` 用 `catch_unwind` 包裹用户 `main`, 这样 `panic!` 不会直接让内核崩溃, 而是被转换为退出码 `101`
- 线程 `guard` 与栈溢出检测: std 运行时会在启动时注册 `SIGSEGV`/`SIGBUS` 处理器, 并记下主线程栈预期的 guard 区间, 这样栈溢出能变成一条可诊断的信息而不是一个裸的信号

这些职责没有地方可放, 它们发生在 `main` **之前** 和 **之后** 所以必须有一个封装层来承载, 而链接到 `libc` 是因为链接一个已经存在的库是最省力的工程选择. `libc` 已经提供了 `_start`, 系统调用封装, 内存分配, 文件 I/O, 线程原语等一整套宿主接口. Rust 的 std 如果要在 Unix 上重新实现这些, 工作量巨大, 收益却很低, 而且会破坏与 C 库的 FFI 互操作性

> 结论: `main` 不是程序入口, 它只是 libc 运行时调用的一个普通函数

## Rust 标准库

上面我们了解了 Rust 标准库的重要性, 下面我们简单认识一下这个习以为常导致经常被忽视的组件

Rust 标准库不是一个整体, 它是 **三个 crate 叠起来的**, 自下而上依次是

- `core`
  - 什么都不需要, 纯语言设施
  - 提供 `Option`, `Result`, `slice`, `str`, `[T; N]` 等
- `alloc`
  - 依赖 `core`
  - 需要一个 **堆**, 但不依赖操作系统
  - 提供 `Vec`, `String`, `Box`, `Rc`, `Arc`, `format!`, `vec!` 等
- `std`
  - 依赖 `alloc` 和 `core`
  - 需要 **操作系统**
  - 提供文件(包括 `println!`), 网络, 线程, 时间, 环境变量, 进程, 默认 panic hook, 栈展开等

> 严格说这三个不是全部. `alloc` 还依赖 `compiler_builtins` (它提供 `memcpy` / `memset` 这类编译器内建符号), `std` 除此之外还依赖 `panic_unwind` / `panic_abort`, `unwind`, `hashbrown`, `libc` 等等. "三个 crate" 是为理解分层而做的简化

对于每个常规 Rust 程序, 编译器都会链接到标准库, 你也可以手动通过 `extern crate std;` 来显示链接到标准库

## 为什么需要 no_std

通过上面, 我们知道常规 Rust 程序构建于 Rust 标准库 std 之上, std 本身是操作系统提供的抽象, 而内核要实现的正是这层抽象

Rust 作为一门系统级语言, 需要在这种裸机环境下工作的能力, 在实现一个与操作系统内核同级别的二进制程序时, 因为没有标准库可用, 所以需要手动阻止链接到标准库

这时就需要 `#![no_std]` 这个标记让编译器不再自动链接到标准库

> 真实机制是 Reference 里的 **extern prelude**: `core` 永远在 extern prelude 里, 而 `std` 只在 crate 根没有写 `#![no_std]` 时才加进去, 同时把 `core` prelude 换成 `std` prelude. 官方文档的原话是 "causes the `std` crate to not be linked automatically".
> 可以通过宏展开命令 `rustc -Zunpretty=expanded hello.rs` 观察到这一点

于是这个 crate 就只能看见 `core`. 如果你还想要 `Vec` 一类的组件, 就自己写一句, `extern crate alloc;`, 但代价是 **你必须提供一个堆**

### 关键认识: 库 ≠ 二进制

`no_std` 不总是要求我们提供一系列的内核组件, 事实上 Rust 生态中有不少 `no_std` 的 crate, 它们只是不依赖标准库. 因此在学习过程中没必要被 `#[panic_handler]` 和全局分配器等卡住

- `no_std` lib
  - 需要 `#![no_std]`
  - 不需要: `panic handler, 全局分配器, 入口点`
  - 可以: 在宿主机上直接 `cargo test`
- `no_std` bin
  - 还需要
    - `#[panic_handler]`: 程序 panic 后谁来收尸
    - `#![no_main]` + 入口点
    - `#[global_allocator]`
    - `extern crate alloc;`
  - 不能: 在宿主机上 cargo run (宿主机上没有裸机运行时)

> 之前我们已经知道 main 是 libc 约定的一个普通函数, 不是语言约定. 裸机没有 libc, 所以这个约定失效了. 但编译器自查依然需要 main 函数, 所以需要 `#![no_main]` 来 **禁用编译器那套 main 包装和 lang_start 机制**, **不要**生成 `main` 这个入口符号", 由我自己提供入口点 `_start`

## 1. 从 std 版本写起

学习 `no_std` 最有效的方式是反过来: 先写一个正常的版本, 然后一件一件把它依赖的东西拿走, 看它在哪一步开始报错, 报什么错.

我们做一个能同时演示几个典型依赖的小工程: 一个固定容量、满了就顶掉最老元素的 **环形缓冲区**, 加上一个解析逗号分隔整数的函数, 再加一个生成报告的辅助函数. 它们分别代表"容器"、"文本处理"和"格式化"三类最常见的需求.

为了方便我会使用一个工作区, 在里面创建一个 `demo-std` 项目

`demo-std/src/main.rs`:

```rust
use std::collections::VecDeque;
use std::fmt;

pub struct HistoryBuffer<T> {
    inner: VecDeque<T>,
    capacity: usize,
}

impl<T> HistoryBuffer<T> {
    pub fn new(capacity: usize) -> Self {
        Self {
            inner: VecDeque::with_capacity(capacity),
            capacity,
        }
    }

    pub fn push(&mut self, value: T) {
        if self.inner.len() == self.capacity {
            self.inner.pop_front();
        }
        self.inner.push_back(value);
    }

    pub fn len(&self) -> usize {
        self.inner.len()
    }

    pub fn is_empty(&self) -> bool {
        self.inner.is_empty()
    }

    pub fn iter(&self) -> impl Iterator<Item = &T> {
        self.inner.iter()
    }
}
```

注意这个类型有两个对 `std` 的隐含依赖: 一是 `VecDeque` 本身(它在 `alloc` 里, 需要堆), 二是 `new(capacity)` 这个签名, **容量是运行时参数**.

继续实现错误类型和文本处理:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ParseError {
    Empty,
    NotANumber,
}

impl fmt::Display for ParseError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            ParseError::Empty => write!(f, "input is empty"),
            ParseError::NotANumber => write!(f, "input is not a number"),
        }
    }
}

impl std::error::Error for ParseError {}

/// 解析一行逗号分隔的十进制整数, 返回它们的和
///
/// 这里用了两种 std 才有的东西: `Vec` 收集中间结果, `parse()` 的错误转换
pub fn sum_csv(line: &str) -> Result<u64, ParseError> {
    let trimmed = line.trim();
    if trimmed.is_empty() {
        return Err(ParseError::Empty);
    }

    let mut total: u64 = 0;
    let parts: Vec<&str> = trimmed.split(',').collect();
    for part in parts {
        let n: u64 = part.trim().parse().map_err(|_| ParseError::NotANumber)?;
        total += n;
    }
    Ok(total)
}

/// 生成一段给用户看的报告, 返回 `String`, 每调用一次就在堆上分配一次
pub fn report(values: &[u64]) -> String {
    let mut out = String::new();
    out.push_str("values: ");
    for (i, v) in values.iter().enumerate() {
        if i > 0 {
            out.push_str(", ");
        }
        // format! 内部又会分配一个临时 String
        out.push_str(&format!("{v}"));
    }
    out.push_str(&format!(" | sum = {}", values.iter().sum::<u64>()));
    out
}

pub fn divide(a: u64, b: u64) -> u64 {
    assert!(b != 0, "division by zero: {a} / {b}");
    a / b
}
```

最后补上 `main` 和两个测试:

```rust
fn main() {
    println!("== demo-std ==");

    let mut history: HistoryBuffer<&str> = HistoryBuffer::new(3);
    for event in ["boot", "init", "mount", "net", "shell"] {
        history.push(event);
    }
    println!("last 3 events: {:?}", history.iter().collect::<Vec<_>>());

    println!("sum_csv(\"1, 2, 3\") = {:?}", sum_csv("1, 2, 3"));
    println!("sum_csv(\"\")        = {:?}", sum_csv(""));
    println!("report             = {}", report(&[3, 1, 4, 1, 5]));
    println!("divide(42, 6)      = {}", divide(42, 6));
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn history_keeps_only_the_latest() {
        let mut h = HistoryBuffer::new(3);
        for v in [1, 2, 3, 4, 5] {
            h.push(v);
        }
        assert_eq!(h.len(), 3);
        assert_eq!(h.iter().copied().collect::<Vec<_>>(), vec![3, 4, 5]);
    }

    #[test]
    fn csv_parsing_works() {
        assert_eq!(sum_csv("1, 2, 3"), Ok(6));
        assert_eq!(sum_csv(""), Err(ParseError::Empty));
        assert_eq!(sum_csv("1, x"), Err(ParseError::NotANumber));
    }
}
```

到这一步, 我们一共有五个对 `std` 的依赖, 后面要一个个拆掉:

- `VecDeque` / `Vec` —— 需要堆
- `String` / `format!` —— 需要堆
- `println!` —— 需要操作系统提供 stdout
- `std::error::Error` —— 只在 `std` 里
- `panic!` + 默认 panic hook —— 需要 std 的 panic 运行时

## 2. 拆掉第一层: 把逻辑搬进 `no_std` 库

新建一个 lib crate `nostd-lib`, 打开 `nostd-lib/src/lib.rs`, 在 **文件最前面** 加上

```rust
#![no_std]
```

现在这个 crate 就看不见 `std` 了. 你可以立刻做个实验: 在 `lib.rs` 里随便敲几句 std 风格的代码

```rust
pub fn a() -> Vec<u8> { Vec::new() }
pub fn b() -> String { String::from("hi") }
pub fn c() { println!("hi"); }
pub fn d() -> f64 { 2.0f64.sqrt() }
```

```txt
error[E0425]: cannot find type `Vec` in this scope
error[E0433]: cannot find type `Vec` in this scope

error[E0425]: cannot find type `String` in this scope
error[E0433]: cannot find type `String` in this scope

error: cannot find macro `println` in this scope

error[E0599]: no method named `sqrt` found for type `f64` in the current scope
```

这几条报错信息值得逐条读一遍, 注意它们的 **措辞**:

- `Vec` 和 `String` 报的是 "找不到这个 **类型**", 不是 "找不到这个 crate". 原因就是上面说的: `alloc` 不在 extern prelude 里, 这两个类型根本没有被引入到当前作用域
- `println` 是"找不到这个 **宏**". `println!` 并不是语言的宏, 它是 `std` 用 `#[macro_export]` 导出的
- 最容易被忽略的是 `sqrt`: **`f64` 的加减乘除在 `no_std` 下完全可用**, 缺的只有 "超越函数". 这一条下面单独讲

> 超越函数, 在数学上指无法用 **有限次四则运算和开方精确表示** 的函数, 如三角函数. 在 Rust 中, 开方操作也包含在其中

但与此同时, 下面这些东西**全部照常可用**, 因为它们都在 `core` 里:

```rust
Option / Result / Iterator / FromIterator
panic! / assert! / debug_assert!
core::fmt（Display / Debug / write!）
slice / str / 数组 / 元组
core::mem / core::ptr / core::cell / core::sync::atomic
core::hint::spin_loop
```

`panic!` 居然还能用, 因为 `panic!` 宏本身在 `core` 里. 它只是需要一个 "谁来收尸" 的实现, 而库不负责提供这个

还有一点, `alloc` 不在 extern prelude 里. 要使用它, 必须显式写

```rust
extern crate alloc;

use alloc::vec::Vec;
use alloc::string::String;
```

而且写了 `extern crate alloc` 之后, **只要用到 `Vec`, 就必须提供一个全局分配器**, 否则链接时报错:

```txt
error: no global memory allocator found but one is required;
       link to std or add `#[global_allocator]` to a static item
       that implements the GlobalAlloc trait
```

注意这个错误是 **链接期** 的, 编译期不报, 因为库不参与链接, 只有二进制才会暴露它

### 2.1 `VecDeque` 没了, 把容量写进类型

回到环形缓冲区. std 版本的关键特征是**容量是运行时参数**, 而这必然意味着堆分配. 没有堆的时候, 只剩一条路: **把容量编进类型**.

新建 `nostd-lib/src/ring.rs`

```rust
use core::mem::MaybeUninit;
use core::ptr;

/// 固定容量, 满了顶掉最老元素的环形缓冲区
///
/// ```txt
///         head（下一个写入位置）
///          |
///   +---+---+---+---+
///   | 3 | 4 |   | 1 |
///   +---+---+---+---+
///              ^
///              tail（下一个读出位置）
///
///   len = 3，逻辑顺序: 1, 3, 4
/// ```
pub struct HistoryBuffer<T, const N: usize> {
    /// `MaybeUninit<T>` 表示 这块内存是给 T 留的, 但现在可能是未初始化的
    buf: [MaybeUninit<T>; N],
    /// 下一个写入位置
    head: usize,
    /// 下一个读出位置
    tail: usize,
    /// 当前元素个数
    len: usize,
}
```

容量 `N` 成了类型参数, 于是:

- 对象大小在编译期就确定, `size_of::<HistoryBuffer<u64, 8>>()` 可以直接算出来
- 不需要分配器, 对象可以放在栈上, 也可以放进 `static`
- 代价是"容量"不再是运行时参数, 不能 `new(runtime_n)`

构造函数要写成 `const fn`, 这样才能出现在 `static` 初始化里:

```rust
impl<T, const N: usize> HistoryBuffer<T, N> {
    pub const fn new() -> Self {
        Self {
            // `[const { ... }; N]` 是 内联 const 表达式 语法
            // 没有它的话, 数组重复初始化语法会要求元素类型是 Copy
            buf: [const { MaybeUninit::uninit() }; N],
            head: 0,
            tail: 0,
            len: 0,
        }
    }

    pub const fn capacity(&self) -> usize { N }
    pub const fn len(&self) -> usize { self.len }
    pub const fn is_empty(&self) -> bool { self.len == 0 }
    pub const fn is_full(&self) -> bool { self.len == N }
}
```

> 数组的重复初始化语法 `[expr; N]` 要求 `expr` 是 `Copy` 的, 而 `MaybeUninit<T>` 只有在 `T: Copy` 时才是 `Copy`. 用内联 const 块把它包起来, 就绕开了这个限制——数组的每个元素都是**独立求值**的常量.

读写用的是裸指针, 因为 `MaybeUninit<T>` 不能直接当 `T` 用:

```rust
impl<T, const N: usize> HistoryBuffer<T, N> {
    /// # Safety
    /// `index` 必须小于 `N`
    #[inline]
    unsafe fn slot(&self, index: usize) -> *const T {
        debug_assert!(index < N);
        // `MaybeUninit<T>` 和 `T` 布局相同, 可以直接把指针转过去
        unsafe { self.buf.as_ptr().add(index).cast::<T>() }
    }

    /// # Safety
    /// `index` 必须小于 `N`
    #[inline]
    unsafe fn slot_mut(&mut self, index: usize) -> *mut T {
        debug_assert!(index < N);
        unsafe { self.buf.as_mut_ptr().add(index).cast::<T>() }
    }

    /// 推入一个元素, 满了就丢掉最老的
    pub fn push(&mut self, value: T) {
        if self.is_full() {
            // 先把最老的取出来丢掉, 腾出 head 的位置
            drop(self.pop());
        }

        // SAFETY: head in [0, N), 且 len < N 时这个槽位一定是未初始化的
        unsafe { ptr::write(self.slot_mut(self.head), value) };

        self.head = (self.head + 1) % N;
        self.len += 1;
    }

    /// 弹出最老的元素
    pub fn pop(&mut self) -> Option<T> {
        if self.is_empty() {
            return None;
        }
        // SAFETY: tail in [0, N) 且该槽位已被 push 初始化过（len > 0）
        // 用 ptr::read 把值搬走, 此后该槽位逻辑上又变回未初始化
        // 所以下面不会重复 drop
        let value = unsafe { ptr::read(self.slot(self.tail)) };
        self.tail = (self.tail + 1) % N;
        self.len -= 1;
        Some(value)
    }

    pub fn peek(&self) -> Option<&T> {
        if self.is_empty() {
            return None;
        }
        // SAFETY: 同 pop()
        Some(unsafe { &*self.slot(self.tail) })
    }

    /// 按逻辑顺序遍历
    pub fn iter(&self) -> impl Iterator<Item = &T> + '_ {
        (0..self.len).map(move |i| {
            let index = (self.tail + i) % N;
            // SAFETY: i < len, 所以这些槽位都已被初始化
            unsafe { &*self.slot(index) }
        })
    }
}
```

**然后是最容易忘的一步**:

```rust
// 别忘了 Drop
// 如果 T 不是 Copy (比如 Box<u8>、String), 不实现 Drop 就直接泄漏
impl<T, const N: usize> Drop for HistoryBuffer<T, N> {
    fn drop(&mut self) {
        // pop() 会把取出的值就地 drop 掉
        while self.pop().is_some() {}
    }
}
```

在 std 环境里, 泄漏几个 `String` 往往无所谓, 进程很快就退出了, 而且还有操作系统去兜底. 但在一个要长期运行的内核里, 泄漏是致命的. 而且 `Drop` 漏掉的 bug **不会被编译器发现**, 单测也往往不会发现, 除非你专门去数.

所以我们专门写一个"数 drop 次数"的测试

```rust
/// 一个会记账的 Drop 类型, 用来验证 `HistoryBuffer` 有没有泄漏
struct DropCounter<'a> {
    counter: &'a core::cell::Cell<u32>,
}

impl Drop for DropCounter<'_> {
    fn drop(&mut self) {
        self.counter.set(self.counter.get() + 1);
    }
}

/// 顶掉老元素时, 那些元素必须被 drop, 而不是泄漏.
#[test]
fn history_buffer_drops_replaced_elements() {
    let dropped = core::cell::Cell::new(0);
    {
        let mut buf: HistoryBuffer<DropCounter<'_>, 4> = HistoryBuffer::new();
        // 塞 10 个进容量 4 的缓冲区: 前 6 个会被顶掉.
        for _ in 0..10 {
            buf.push(DropCounter { counter: &dropped });
        }
        assert_eq!(buf.len(), 4);
        assert_eq!(dropped.get(), 6);
    }
    // 出了作用域, 剩下的 4 个也必须被 drop. 一共 10 次, 没有泄漏.
    assert_eq!(dropped.get(), 10);
}
```

最后顺手把迭代器实现也补上, 这样它和 std 版本的用法一致:

```rust
impl<'a, T, const N: usize> IntoIterator for &'a HistoryBuffer<T, N> {
    type Item = &'a T;
    type IntoIter = HistoryIter<'a, T, N>;

    fn into_iter(self) -> Self::IntoIter {
        HistoryIter { buf: self, index: 0 }
    }
}

pub struct HistoryIter<'a, T, const N: usize> {
    buf: &'a HistoryBuffer<T, N>,
    index: usize,
}

impl<'a, T, const N: usize> Iterator for HistoryIter<'a, T, N> {
    type Item = &'a T;

    fn next(&mut self) -> Option<Self::Item> {
        if self.index >= self.buf.len {
            return None;
        }
        let slot = (self.buf.tail + self.index) % N;
        self.index += 1;
        // SAFETY: index < len, 槽位一定被初始化过
        Some(unsafe { &*self.buf.slot(slot) })
    }

    fn size_hint(&self) -> (usize, Option<usize>) {
        let remaining = self.buf.len - self.index;
        (remaining, Some(remaining))
    }
}

impl<T, const N: usize> ExactSizeIterator for HistoryIter<'_, T, N> {}
```

### 2.2 `String` 没了: 写一个固定容量的静态版本

`String` 住在 `alloc` 里, 它要堆. 但请注意一件事: **纯文本处理本身完全不需要 `std`**. `str` 的方法、`char`, 切片, `core::fmt` 的格式化, 全都在 `core` 里. 真正缺的只有"动态增长".

新建 `nostd-lib/src/fixed_str.rs`:

```rust
use core::fmt;
use core::str;

/// 固定容量的 UTF-8 字符串
pub struct FixedString<const N: usize> {
    /// 有效字节在 `buf[..len]` 里, 且**保证是合法的 UTF-8**
    buf: [u8; N],
    len: usize,
}

/// 放不下时返回的错误
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct CapacityError;

impl fmt::Display for CapacityError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.write_str("fixed-capacity string is full")
    }
}
```

注意 `CapacityError` 只实现了 `fmt::Display` 和 `Debug`, **没有** 实现 `std::error::Error`, 因为后者只在 `std` 里. 这是拆掉第四个依赖的方式: 少一层 trait 而已, 用户看到的错误消息一点没少.

写接口的时候, 有一个设计决定值得停一下:

```rust
impl<const N: usize> FixedString<N> {
    pub const fn new() -> Self {
        Self { buf: [0; N], len: 0 }
    }

    pub const fn len(&self) -> usize { self.len }
    pub const fn is_empty(&self) -> bool { self.len == 0 }
    pub const fn capacity(&self) -> usize { N }
    pub const fn remaining(&self) -> usize { N - self.len }

    pub fn clear(&mut self) {
        self.len = 0;
    }

    /// 以 `&str` 的形式查看内容
    pub fn as_str(&self) -> &str {
        // SAFETY: 类型不变量保证 buf[..len] 是合法 UTF-8
        unsafe { str::from_utf8_unchecked(&self.buf[..self.len]) }
    }

    /// 追加一段 `&str`. 放不下时返回 `Err` 且**不做任何修改**
    pub fn push_str(&mut self, s: &str) -> Result<(), CapacityError> {
        let bytes = s.as_bytes();
        if self.remaining() < bytes.len() {
            return Err(CapacityError);
        }
        self.buf[self.len..self.len + bytes.len()].copy_from_slice(bytes);
        self.len += bytes.len();
        Ok(())
    }

    /// 追加一个 `u64` 的十进制表示, 完全不分配
    pub fn push_u64(&mut self, mut n: u64) -> Result<(), CapacityError> {
        let mut digits = [0u8; 20];
        let mut i = digits.len();
        loop {
            i -= 1;
            digits[i] = b'0' + (n % 10) as u8;
            n /= 10;
            if n == 0 {
                break;
            }
        }
        // SAFETY: digits 里全是 ASCII 数字, 必然是合法 UTF-8
        let s = unsafe { str::from_utf8_unchecked(&digits[i..]) };
        self.push_str(s)
    }
}
```

关键在于 `push_str` 的返回值: `String::push_str` 是不返回 `Result` 的(它不会失败), 而这里**必须**返回 `Result`. 这就是"动态分配换成固定容量"的核心代价. 每一个可能溢出的操作都要让调用者知道.

顺便把 `fmt::Write` 也实现上, 于是 `write!` 还能用:

```rust
/// 实现 `core::fmt::Write`, 于是 `write!(fs, "x = {}", 1)` 也能用
impl<const N: usize> fmt::Write for FixedString<N> {
    fn write_str(&mut self, s: &str) -> fmt::Result {
        self.push_str(s).map_err(|_| fmt::Error)
    }
}
```

到这里, `report()` 那个返回 `String` 的函数, 就可以改造成"往调用者的缓冲区里写":

```rust
/// 把格式化结果写进调用者提供的缓冲区。
///
/// 这是 `no_std` 世界里非常典型的函数签名, 内存由调用者提供
pub fn write_report<const N: usize>(
    out: &mut FixedString<N>,
    values: &[u64],
) -> Result<(), CapacityError> {
    use fmt::Write as _;

    let mut first = true;
    write!(out, "values: ").map_err(|_| CapacityError)?;
    for v in values {
        // 注意这里只借用了 out, 没有产生任何临时 String
        write!(out, "{}{v}", if first { "" } else { ", " }).map_err(|_| CapacityError)?;
        first = false;
    }
    write!(out, " | sum = {}", values.iter().sum::<u64>()).map_err(|_| CapacityError)
}
```

### 2.3 `core` 缺的那一块: 浮点超越函数

这是最容易让人误判的一条报错:

```rust
let x = 2.0f64.sqrt();
```

```txt
error[E0599]: no method named `sqrt` found for type `f64` in the current scope
```

看起来像是 `no_std` 不能算浮点, 其实不然. 真实原因是: `sqrt`, `sin`, `ln`, `powf` 这些 **超越函数** 的实现体在 `libm` 里 (一个 C 数学库), `core` 为了保持零依赖不链接它. **四则运算 `+ - * /` 是照常可用的**, 比较, `to_bits`, `from_bits` 也都在.

两个可行的处理方式:

1. 自己写算法. 比如整数平方根用牛顿迭代就够了:

```rust
pub fn isqrt(n: u64) -> u64 {
    if n < 2 {
        return n;
    }
    let bits = 64 - n.leading_zeros(); // n 的有效位数
    let mut x = 1u64 << ((bits + 1) / 2); // 一个 >= sqrt n 的初值
    loop {
        // x_(k+1) = (x_k + n / x_k) / 2
        let y = (x + n / x) / 2;
        if y >= x {
            return x;
        }
        x = y;
    }
}
```

2. 用 `libm` crate. 它是纯 Rust 重写的 `libm`, 可以在 `no_std` 下用:

```toml
[dependencies]
libm = "0.2"
```

```rust
let x = libm::sqrt(2.0);
```

```rust
/// 向上取整到 `align` 的倍数, 写分配器时的必备工具
///
/// `align` 必须是 2 的幂
pub const fn align_up(addr: usize, align: usize) -> usize {

    (addr + align - 1) & !(align - 1)
}
```

## 3. 交叉编译

`cargo test` 通过只说明"在宿主机上能跑". 要证明库本身不依赖 `std`, 最直接的办法是**交叉编译到一个根本没有 `std` 的目标**

```bash
rustup target add thumbv7em-none-eabihf
cargo build -p nostd-lib --target thumbv7em-none-eabihf
```

`thumbv7em-none-eabihf` 是 Rust 的 **Tier 2** 目标, rustup 会分发**预编译好的** `core` 和 `alloc`, 所以不需要 nightly, 不需要 `-Zbuild-std`, 也不需要 `rust-src` 组件, 一条 `rustup target add` 就够了.

更重要的是, 它可以很方便的 **在 QEMU 里直接跑起来**, 方便后面我们做一些验证

这一步一旦混进 `std::` 的东西, 会立刻报错. 因为 `thumbv7em-none-eabihf` 只提供 `core` 和 `alloc`. 可以拿上一节那段 `std::mem::MaybeUninit` 的实验验证一下: 把 `ring.rs` 里的 `use core::mem::MaybeUninit;` 改成 `use std::mem::MaybeUninit;`, 再交叉编译一次.

## 4. 把它变成二进制

接下来新建 bin crate `nostd-bin`

`nostd-bin/src/main.rs` 先写下最朴素的形态, 只把 `#![no_std]` 加上:

```rust
#![no_std]

fn main() {}
```

```bash
cargo build -p nostd-bin --target thumbv7em-none-eabihf
```

```txt
error: `#[panic_handler]` function required, but not found
```

注意编译器**只报了这一条**. 它是硬错误, 所以你暂时看不到别的. 补上 panic handler 之后再看:

```rust
#![no_std]

use core::panic::PanicInfo;

#[panic_handler]
fn p(_: &PanicInfo) -> ! { loop {} }

fn main() {}
```

```txt
error: using `fn main` requires the standard library
  |
  = help: use `#![no_main]` to bypass the Rust generated entrypoint and declare a
          platform specific entrypoint yourself, usually with `#[no_mangle]`
```

这两条报错连起来看, 结论很清楚: **编译器要的从来不是"有没有 libc", 而是一个入口符号**. 要么给它 `fn main`, 要么写 `#![no_main]` 然后自己提供入口点, 不能两个都不给.

> 重复一遍: `#![no_main]` **不是**"禁止 `main`". 它的语义是"不要生成 `main` 这个入口符号". 所以如果你写了 `#![no_main]` 又留着一个 `fn main`, 那个函数会变成没人调用的死代码(`dead_code` 警告), 而链接器会另外抱怨找不到入口:
>
> ```txt
> warning: linker stderr: rust-lld: cannot find entry symbol _start; not setting start address
> ```
>
> 这些链接期的抱怨默认只是 warning, 所以**产出一个跑不起来的映像也可能"构建成功"**

### 4.1 入口点

在宿主机上, 一个二进制能跑起来, 是因为有操作系统在背后做了这些事:

- **设置栈指针**: 刚加载时栈指针是垃圾值, 而调用任何函数都要用栈;
- **清零 `.bss`**: Rust 假设所有 `static` 已经归零, 这是 loader 的职责;
- **搬运 `.data`**: `static X: u32 = 42` 的初值存在 flash/磁盘里, 得有人把它拷到 RAM;
- **准备向量表**(在 ARM 上): CPU 上电后从固定的表里读"栈顶在哪、第一条指令在哪".

在裸机上这些需要靠我们自己完成

- 自己用 `naked_asm!` 写一段 `_start`: 完全掌控, 但要处理上面四件事
- 交给平台 crate: 例如 Cortex-M 上的 `cortex-m-rt`, 它同样是一个 no_std crate

我们选择后者, 将重点留在 `no_std` 本身而不是一些汇编. 先加上依赖 `nostd-bin/Cargo.toml`:

```toml
[dependencies]
nostd-lib = { path = "../nostd-lib" }

# cortex-m-rt 提供 Reset 之后的启动代码
cortex-m-rt = { version = "0.7", features = ["set-sp"] }
# semihosting 让 guest 通过调试通道直接往 QEMU 的宿主终端写字
cortex-m-semihosting = "0.5"
```

然后入口点就只是这样一个普通函数:

```rust
use cortex_m_rt::entry;

/// 程序的入口点.
///
/// 注意这里没有汇编, 也没有 `#[unsafe(no_mangle)]`:
/// 栈指针、.bss 清零、.data 搬运这些事由 cortex-m-rt 的 Reset
/// 在调用这个函数之前做完. 在宿主操作系统上, 这些是 loader 的工作.
///
/// `#[entry]` 会把函数导出成 `main` 符号, 并保证签名是 `fn() -> !`.
#[entry]
fn kernel_main() -> ! {
    // ...
    loop {
        core::hint::spin_loop();
    }
}
```

**对比一下 x86 上同样的事**: 因为 x86 没有一个等效的 `cortex-m-rt`, 那段 `_start` 得自己写, 而且必须是裸汇编:

```rust
// 在 x86_64-unknown-none 上你得自己写这个, 而且只能用 sym / const 两种操作数
#[unsafe(naked)]
#[unsafe(no_mangle)]
#[unsafe(link_section = ".text.entry")]
unsafe extern "C" fn _start() -> ! {
    core::arch::naked_asm!(
        "lea  rsp, [rip + {stack} + {stack_size}]",   // 设栈
        "and  rsp, -16",
        "movabs rdi, offset __bss_start",             // 清 .bss
        "movabs rcx, offset __bss_end",
        "1:",
        "    cmp  rdi, rcx",
        "    jae  2f",
        "    mov  byte ptr [rdi], 0",
        "    inc  rdi",
        "    jmp  1b",
        "2:",
        "call kernel_main",
        "3:",
        "    hlt",
        "    jmp  3b",
        stack      = sym STACK,
        stack_size = const 16 * 1024,
    )
}
```

两种写法的目的完全一样, 差别只在于"这些活有没有现成的 crate 干".

> `#[unsafe(no_mangle)]`、`#[unsafe(link_section)]` 这类 **unsafe attribute**, 在 **edition 2024 里必须写成 `unsafe(...)` 包裹的形式**. 而 `#[unsafe(naked)]` 本身是 2025 年随 Rust 1.88 才稳定的, 在它之前只能靠 `global_asm!` 手写 `.section` / `.globl`.

既然用了 `cortex-m-rt`, 还得告诉它"内存有多大、从哪开始". 它会 `INCLUDE` 一个叫 `memory.x` 的文件, 所以这个文件必须放在**运行 cargo 时的工作目录**(也就是工程根目录):

```txt
/*
 * 这块板子的内存布局.
 *
 * cortex-m-rt 自带的 link.x 会 INCLUDE 这个文件, 并据此放置
 * 向量表、.text .data .bss 和栈.
 *
 * FLASH 的起始地址必须和 QEMU 机器匹配: lm3s6965evb 的 flash 从
 * 0x00000000 开始, 向量表必须落在 0 地址. 如果按别的板子写成 0x08000000,
 * QEMU 起跳时读不到向量表, 会直接 "Lockup: can't escalate 3 to HardFault".
 */
MEMORY
{
    FLASH : ORIGIN = 0x00000000, LENGTH = 256K
    RAM   : ORIGIN = 0x20000000, LENGTH = 64K
}
```

最后把构建参数写成工程里的别名 `demo/.cargo/config.toml`:

```toml
[alias]
bare = "build -p nostd-bin --target thumbv7em-none-eabihf --config target.thumbv7em-none-eabihf.rustflags=['-C','link-arg=-Tlink.x']"
```

`-Tlink.x` 就是 `cortex-m-rt` 自带的那份链接脚本(它会 include 我们的 `memory.x`). 之后一条 `cargo bare` 就够了.

### 4.2 最小 `panic_handler`

`#[panic_handler]` 是任何 `no_std` 二进制都必须提供的, 和你有没有用到 `panic!` 无关. 刚刚我们临时使用一个死循环实现, 什么都没做. 现在我们实现一个最小版本

不过我们还没有任何输出设备, 所以只要能编过, 并且让失败可被观测就够了

```rust
use core::panic::PanicInfo;
use cortex_m_semihosting::debug;

/// 最小可用的 panic 处理器: 不打印任何东西, 只让 QEMU 以失败码退出.
#[panic_handler]
fn panic(_info: &PanicInfo) -> ! {
    // 让 QEMU 直接结束进程(退出码非 0)
    debug::exit(debug::EXIT_FAILURE);
    loop {
        core::hint::spin_loop();
    }
}
```

两个细节:

- 函数参数是 `#[panic_handler]` 的约定, 不能省略;
- `debug::exit` 只在有调试器(QEMU)时生效, 真机上会直接返回, 所以后面必须跟一个停机循环.

### 4.3 `println!`

新建 `nostd-bin/src/console.rs`

这一步和硬件无关, 是纯粹的 `core::fmt` 用法

```rust
use core::fmt;

/// 一个"写到 semihosting stdout"的 `core::fmt::Write` 实现
pub struct HostWriter;

/// 实现 `core::fmt::Write`, 它只有一个必需方法
///
/// 只要实现了它, `write!`, `writeln!`, `format_args!` 就全部可用
impl fmt::Write for HostWriter {
    fn write_str(&mut self, s: &str) -> fmt::Result {
        // cortex-m-semihosting 已经封装好了细节
        cortex_m_semihosting::hio::hstdout()
            .map_err(|_| fmt::Error)?
            .write_str(s)
            .map_err(|_| fmt::Error)
    }
}

#[macro_export]
macro_rules! println {
    () => {{
        use core::fmt::Write as _;
        let _ = writeln!($crate::console::HostWriter);
    }};
    ($($arg:tt)*) => {{
        use core::fmt::Write as _;
        let _ = writeln!($crate::console::HostWriter, $($arg)*);
    }};
}
```

**整条链路上没有任何内存分配**: `core::fmt` 是边格式化边写出去的, `Formatter` 把结果直接喂给 `write_str`, 不存在中间 `String`. 所以 `println!("x = {}", x)` 在 `no_std` 里照常可用, 只要 `x` 实现了 `Display`.

同一套套路可以用在任何"能写字节"的地方:

```txt
write!(sink, "...") ──> 只要 sink 实现了 core::fmt::Write
                         ├── semihosting (本节的 HostWriter)
                         ├── 串口 UART (内存映射寄存器)
                         ├── SBI 控制台 (ecall, RISC-V)
                         ├── 内存缓冲区 (下面 logbuf.rs)
                         └── 你自己的任何东西
```

另外还有一个**纯内存**的实现值得看, 它才是本教程真正想强调的例子, 因为"输出"这件事和硬件无关, 而且它能在宿主机上被单测.

新建 `nostd-bin/src/logbuf.rs`:

```rust
//! 一个**没有任何硬件依赖**的 `core::fmt::Write` 实现: 往内存里的缓冲区写日志

use core::cell::UnsafeCell;
use core::fmt;

/// 固定容量的日志缓冲区
pub struct LogBuffer<const N: usize> {
    buf: [u8; N],
    len: usize,
    /// 因为放不下而丢掉了多少字节, 静默截断是不可接受的
    /// 调用者至少要知道, 这里丢过东西
    dropped: usize,
}

impl<const N: usize> LogBuffer<N> {
    pub const fn new() -> Self {
        Self { buf: [0; N], len: 0, dropped: 0 }
    }

    pub const fn len(&self) -> usize {
        self.len
    }

    /// 已经丢掉的字节数
    pub const fn dropped(&self) -> usize {
        self.dropped
    }

    /// 以 `&str` 的形式查看内容
    pub fn as_str(&self) -> &str {
        // SAFETY: 由类型不变量保证
        unsafe { core::str::from_utf8_unchecked(&self.buf[..self.len]) }
    }
}

impl<const N: usize> fmt::Write for LogBuffer<N> {
    fn write_str(&mut self, s: &str) -> fmt::Result {
        let bytes = s.as_bytes();
        let n = core::cmp::min(bytes.len(), N - self.len);
        self.buf[self.len..self.len + n].copy_from_slice(&bytes[..n]);
        self.len += n;
        // 放不下的部分只能丢掉
        // 注意: 这里不能返回 Err, 日志缓冲区满了不该让整个程序崩掉
        self.dropped += bytes.len() - n;
        Ok(())
    }
}

impl<const N: usize> Default for LogBuffer<N> {
    fn default() -> Self {
        Self::new()
    }
}

/// 把 `LogBuffer` 变成可以放进 `static` 的类型
#[repr(transparent)]
pub struct SharedLog<const N: usize>(UnsafeCell<LogBuffer<N>>);

// SAFETY: 调用方必须保证不会真正并发地访问它
unsafe impl<const N: usize> Sync for SharedLog<N> {}

impl<const N: usize> SharedLog<N> {
    pub const fn new() -> Self {
        Self(UnsafeCell::new(LogBuffer::new()))
    }

    /// 拿到内部缓冲区的裸指针
    pub const fn get(&self) -> *mut LogBuffer<N> {
        self.0.get()
    }
}

#[cfg(test)]
mod tests {
    use super::*;
    use core::fmt::Write;

    #[test]
    fn formats_without_any_allocation() {
        let mut log = LogBuffer::<64>::new();
        write!(log, "hello {}, answer = {}", "world", 42).unwrap();
        assert_eq!(log.as_str(), "hello world, answer = 42");
    }

    #[test]

        let mut log = LogBuffer::<8>::new();
        write!(log, "0123456789").unwrap();

### 4.4 全局分配器

到这里二进制已经能编过了, 但还没有堆.

`alloc` 里所有类型都建立在一个假设上: **存在一个全局分配器**. 这个假设用一条 trait 表达:

```rust
pub unsafe trait GlobalAlloc {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8;      // 给我一块内存
    unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout); // 还给你
    // alloc_zeroed / realloc 有默认实现，可以先不管
}
```

注意 `GlobalAlloc` 到今天仍然是 **`unsafe trait` 加 `unsafe fn`**, edition 2024 没有改它的签名

#### 4.4.1 库分配算法

和其他逻辑一样, 先把**算法**写进 `nostd-lib`, 这样它能被单测覆盖. 我们实现最简单的一类: **bump allocator**.

新建 `nostd-lib/src/bump.rs`

```txt
  堆的起点                        bump 指针                    堆的终点
    |                                |                             |
    v                                v                             v
    +-------------+------------------+-----------------------------+
    |  已分配…     |      已分配       |        还没用过              |
    +-------------+------------------+-----------------------------+
```

`BumpHeap` **自己不带内存**, 而是从调用者那里接收一块 `&mut [u8]`. 好处有三个:

1. 在宿主机上可以用普通数组测它, 全部逻辑都能被 `cargo test` 覆盖
2. 真正做全局分配器时, 这块内存可以放在 `.bss` 里的静态数组, 也可以来自页分配器
3. 一个程序里可以有多个独立的堆, 测试之间互不干扰

```rust
use core::alloc::Layout;
use crate::math::align_up;

/// 分配失败的原因
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum BumpError {
    /// 加上对齐填充后, 剩余空间不够
    OutOfMemory {
        /// 调用者要求的字节数, 含填充
        requested: usize,
        /// 当前还剩多少字节
        remaining: usize,
    },
    /// 地址运算溢出, 理论上的边界情况
    Overflow,
}

/// 一个 只增不减 的堆
///
/// 它借用那块内存, 所以编译器会保证 堆的寿命不会超过它管的那块内存
pub struct BumpHeap<'a> {
    /// 整块可用内存
    arena: &'a mut [u8],
    /// 下一个空闲字节相对 `arena` 起点的偏移
    offset: usize,
    /// 统计为了对齐浪费掉多少字节
    padding_wasted: usize,
}
```

分配的核心只有三个动作: 对齐, 检查, 推进

```rust
impl<'a> BumpHeap<'a> {
    pub fn new(arena: &'a mut [u8]) -> Self {
        Self { arena, offset: 0, padding_wasted: 0 }
    }

    pub fn remaining(&self) -> usize { self.arena.len() - self.offset }
    pub fn padding_wasted(&self) -> usize { self.padding_wasted }

    /// 分配一块内存, 返回它的起始地址
    ///
    /// 返回地址而不是指针, 是为了让测试不需要 `unsafe`
    /// 真正的 `GlobalAlloc` 实现会把它转成指针
    pub fn allocate(&mut self, layout: Layout) -> Result<usize, BumpError> {
        let base = self.arena.as_ptr() as usize;

        // 当前空闲区的起始地址
        let current = base.checked_add(self.offset).ok_or(BumpError::Overflow)?;
        // 对齐到 layout.align()
        let aligned = align_up(current, layout.align());
        let padding = aligned - current;

        // 对齐之后还要放得下 size 字节
        let end_offset = self
            .offset
            .checked_add(padding)
            .and_then(|v| v.checked_add(layout.size()))
            .ok_or(BumpError::Overflow)?;

        if end_offset > self.arena.len() {
            return Err(BumpError::OutOfMemory {
                requested: layout.size() + padding,
                remaining: self.remaining(),
            });
        }

        self.offset = end_offset;
        self.padding_wasted += padding;
        Ok(aligned)
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    /// 造一个 256 字节, 16 字节对齐的测试用堆
    #[repr(align(16))]
    struct Arena([u8; 256]);

    fn with_arena<R>(f: impl FnOnce(&mut BumpHeap<'_>) -> R) -> R {
        let mut arena = Arena([0; 256]);
        let mut heap = BumpHeap::new(&mut arena.0);

    #[test]
    fn allocations_are_aligned() {
        with_arena(|heap| {

#### 4.4.2 接到 `GlobalAlloc`

现在回到二进制, 新建 `nostd-bin/src/heap.rs`:

```rust
use core::alloc::{GlobalAlloc, Layout};
use core::cell::UnsafeCell;
use core::sync::atomic::{AtomicUsize, Ordering};

/// 静态堆的大小. 我们的测试中, 16 KiB 基本足够
const HEAP_SIZE: usize = 16 * 1024;

/// 静态堆本体
///
/// - `UnsafeCell` 内部可变性
/// - `repr(align(16))` 保证堆起点至少 16 字节对齐
/// - `unsafe impl Sync` 下面所有偏移量访问都经过原子操作
///   所以并发调用 `alloc` 也不会拿到重叠的区间
#[repr(align(16))]
struct Arena(UnsafeCell<[u8; HEAP_SIZE]>);

// SAFETY: 唯一会写这块内存的是 Bump::alloc,
//         它用 compare_exchange 保证不同 CPU 不会拿到重叠的区间
unsafe impl Sync for Arena {}

/// 只增不减的分配器
struct Bump {
    arena: Arena,
    /// 下一个空闲字节相对 arena 起点的偏移
    offset: AtomicUsize,
    /// 统计分配次数
    count: AtomicUsize,
    /// 统计历史最高水位
    peak: AtomicUsize,
}

impl Bump {
    const fn new() -> Self {
        Self {
            arena: Arena(UnsafeCell::new([0; HEAP_SIZE])),
            offset: AtomicUsize::new(0),
            count: AtomicUsize::new(0),
            peak: AtomicUsize::new(0),
        }
    }

    /// 把偏移向上对齐到 `align`（`align` 必须是 2 的幂）。
    ///
    /// 实现和 `nostd-lib::math::align_up` 一样，只是这里作用在**偏移量**
    /// 而不是绝对地址上 —— 效果等价，但少一次基址加法。
    #[inline]
    const fn align_up(offset: usize, align: usize) -> usize {
        // align 是 2 的幂 ⇒ (align - 1) 是一串 1，取反就是掩码。
        (offset + align - 1) & !(align - 1)
    }
}
```

和库里的版本相比, 这里多了原子操作, 因为全局分配器必须是线程安全的:

```rust
unsafe impl GlobalAlloc for Bump {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        // layout.size() == 0 是 UB
        // `Vec` 在 T 是零大小类型时不会走分配器, 但别的调用方可能会
        if layout.size() == 0 {
            return core::ptr::null_mut();
        }

        let base = self.arena.0.get().cast::<u8>() as usize;
        let align = layout.align().max(1);
        let mut current = self.offset.load(Ordering::Relaxed);

        loop {
            // 1) 把当前偏移对齐
            let start = match current.checked_add(align - 1) {
                Some(_) => Self::align_up(current, align),
                None => return core::ptr::null_mut(),
            };
            // 2) 检查是否放得下
            let end = match start.checked_add(layout.size()) {
                Some(end) if end <= HEAP_SIZE => end,
                // 放不下就返回空指针. **注意**: 这里不要 panic
                // 因为 `alloc` 的契约是 失败返回 null
                // 接下来是 panic 还是别的处理由 alloc crate 决定
                _ => return core::ptr::null_mut(),
            };
            // 3) 用 CAS 抢占 [start, end) 这段区间
            match self.offset.compare_exchange_weak(
                current, end, Ordering::Relaxed, Ordering::Relaxed,
            ) {
                Ok(_) => {
                    self.count.fetch_add(1, Ordering::Relaxed);
                    self.peak.fetch_max(end, Ordering::Relaxed);
                    // SAFETY: [start, end) 落在 arena 内, 且刚被我们独占
                    return unsafe { (base as *mut u8).add(start) };
                }
                // 别人抢先改了 offset, 拿到新值重试
                Err(actual) => current = actual,
            }
        }
    }

    unsafe fn dealloc(&self, _ptr: *mut u8, _layout: Layout) {
        // bump allocator 不复用
    }
}

/// 注册全局分配器, 整个程序里 只能有一个
#[global_allocator]
static ALLOCATOR: Bump = Bump::new();
```

四个设计要点, 每一个都是"在 std 里不会想到, 在 `no_std` 里必须想"的:

| 要点 | 原因 |
|------|--------|
| `layout.size() == 0` 返回 null | `GlobalAlloc` 文档明确说零大小 layout 是 **UB** |
| 分配失败**返回 null**, 不 panic | 这是 `alloc` 的契约; 接下来怎么办由 `alloc` crate 决定 |
| 用 `checked_add` 而不是 `+` | 内核代码不能假设地址运算不会溢出 |
| 用 `compare_exchange_weak` | 即使单核也要注意, `fetch_add` 会在多核下重叠 |

最后在加一些辅助函数

```rust
/// 当前已被占走的字节数, 含对齐填充
pub fn used() -> usize {
    ALLOCATOR.offset.load(Ordering::Relaxed)
}

/// 历史最高水位
pub fn peak() -> usize {
    ALLOCATOR.peak.load(Ordering::Relaxed)
}

/// 分配次数
pub fn alloc_count() -> usize {
    ALLOCATOR.count.load(Ordering::Relaxed)
}

/// 堆的总容量
pub const fn capacity() -> usize {
    HEAP_SIZE
}
```

// 之后 `Vec`, `String`, `Box`, `format!` 才可见

#[entry]
fn kernel_main() -> ! {
    println!("==============================================");
    println!("  rust no_std tour / stage 3");
    println!("  target : thumbv7em-none-eabihf (Cortex-M)");
    println!("  running in QEMU lm3s6965evb");
    println!("==============================================");

    // 1. core 里的东西: 完全不需要堆
    let mut history: HistoryBuffer<&str, 3> = HistoryBuffer::new();
    for event in ["boot", "init", "mount", "net", "shell"] {
        history.push(event);
    }
    println!("[core]  last 3 events (no heap at all):");
    for event in &history {
        println!("          - {}", event);
    }

    let mut fs: FixedString<32> = FixedString::new();
    let _ = fs.push_str("fixed:");
    let _ = fs.push_u64(2026);
    println!("[core]  FixedString = {}", fs.as_str());

    // 2. alloc 里的东西: 现在有堆了
    let mut v: Vec<u32> = Vec::new();
    let (mut a, mut b) = (0u32, 1u32);

        v.push(a);
        let next = a.wrapping_add(b);
        a = b;
        b = next;

    s.push_str("no_std");
    s.push('!');
    println!("[alloc] String   = {}", s);

        "{} fib numbers, sum = {}",
        v.len(),
        v.iter().map(|x| *x as u64).sum::<u64>()

            println!("        try_reserve returned Err: {e:?}");
            println!("        ... and the program keeps running");
        }

    let before = heap::used();

        let mut big: Vec<u8> = Vec::new();
        big.try_reserve(2 * 1024).ok();
        big.resize(2 * 1024, 7);
        println!("        while alive, used = {}", heap::used());

    let mut raw = [0u8; 64];

到这里, `kernel_main` 里用的是 4.2 那个**最小的** `panic_handler`. 它已经够用了, 但我们花了那么大力气做出 `println!`, 显然希望内核崩溃时能说清楚"崩在哪, 为什么". 所以最后把它补完.

> **输出只用 ASCII**, 以防乱码

### 4.6 把 `panic_handler` 补完

```rust
use core::panic::PanicInfo;

/// panic 处理器: `no_std` 二进制**必须**提供, 且全程序只能有一个
///
/// 三条规则
///   1. 不能再 panic, 否则无限递归, 所以只用 `write!`, 不用 `format!`
///   2. 尽量不分配内存, 分配器本身可能会出问题
///   3. 把位置和消息都打出来, 方便定位
#[panic_handler]
fn panic(info: &PanicInfo) -> ! {
    println!();
    println!("!!! kernel panic !!!");
    // `location()` 返回 Option, 编译器可能没法给出位置
    if let Some(location) = info.location() {
        println!("  at {}:{}:{}", location.file(), location.line(), location.column());
    }
    // `message()` 是 Rust 1.81 起稳定的接口, 返回实现了 `Display` 的 PanicMessage
    println!("  message: {}", info.message());
    println!("(exiting with failure)");

    debug::exit(debug::EXIT_FAILURE);
    loop {
        core::hint::spin_loop();
    }
}
```

`println!` 只调用 `write_str`, **不分配内存**, 所以它可以用在 `panic_handler` 里; 而 `format!` 不行, 它要先在堆上开一块 `String`. 在一个"分配器本身可能已经坏了"的时刻, 这个区别是致命的.

最后一行是 `debug::exit` 让 QEMU 自己退出的, 退出码 0. 没有它的话就得手动按 `Ctrl-A X`.

注意这里发生了什么: 这段代码**没有任何操作系统, 没有任何驱动, 没有 `std`**. 但它打印了 30 个斐波那契数, 一个 `String`, 一个 `format!` 的结果, 以及一个 `Vec` 的调试输出.

简单看一下编译产物

```bash
llvm-objdump -f target/thumbv7em-none-eabihf/debug/nostd-bin
```

```txt
target/thumbv7em-none-eabihf/debug/nostd-bin:  file format elf32-littlearm
architecture: arm
start address: 0x00000401
```

入口地址 `0x00000401` 的最后一位是 1 —— 这是 ARM Thumb 模式的标志位, 很正常. 再看段布局:

```bash
llvm-objdump -h target/thumbv7em-none-eabihf/debug/nostd-bin
```

```txt
Idx Name            Size     VMA      Type
  1 .vector_table   00000400 00000000 DATA
  2 .text           0000743c 00000400 TEXT
  3 .rodata         00002dd4 0000783c DATA
  4 .data           00000000 20000000 DATA
  6 .bss            000040a0 20000000 BSS
```

`0x00000000` 处的 `.vector_table` 就是前面说的中断向量表, 它由 `cortex-m-rt` 生成; `.bss` 落在 RAM 里, 占了 0x40a0 字节(约 16 KiB —— 我们那个静态堆就在里面).

关键符号也都在:

```bash
llvm-objdump -t target/thumbv7em-none-eabihf/debug/nostd-bin | findstr "Reset main __sbss __ebss _stack_start"
```

```txt
00000400 g     F .text	00000044 Reset
00005880 g     F .text	00000000 DefaultHandler
00001d8a g     F .text	00000008 main
20010000 g       *ABS*	00000000 _stack_start
20000000 g       .bss	00000000 __sbss
200040a0 g       .bss	00000000 __ebss
```

`Reset` 是 CPU 上电后真正执行的第一条指令(由 `cortex-m-rt` 提供), `main` 就是我们的 `kernel_main`.

最后, 也是最重要的一步 —— 看看它到底依赖了什么:

```bash
llvm-objdump -t target/thumbv7em-none-eabihf/debug/nostd-bin | findstr std
# 期望: 没有任何输出, 一个 std 符号都没有
```

一个 `std` 符号都没有, 但程序能打印, 能分配, 能格式化. 这就是 `no_std` 的全部意义.

### 版本时效性备忘

写这篇的时候按 **Rust 1.100 nightly edition 2024**. 下面是一些在当前版本过时但可能在更老的教程中看到的内容

| 版本 | 变化 | 影响 |
|------|------|------|
| 1.68 (2023-03) | `alloc` 分配失败默认 `panic!` | **不再需要** `#[alloc_error_handler]`; 想可失败就用 `try_reserve` |
| 1.77 (2024-03) | `static_mut_refs` 警告 | 不要对 `static mut` 取引用 |
| 1.79 (2024-06) | 内联 const 表达式稳定 | 才能写 `[const { MaybeUninit::uninit() }; N]` |
| 1.81 (2024-09) | `PanicInfo::message()` 稳定, `payload()` 废弃 | panic handler 的正确写法 |
| 1.82 (2024-10) | `&raw const`, `&raw mut`, unsafe attribute 可选写法 | 全局可变状态 |
| 1.85 (2025-02) | **Edition 2024** | `unsafe extern`, unsafe attribute, `static_mut_refs` deny |
| 1.86 (2025-04) | `#[start]`, `#![feature(start)]` 被移除 | 老教程的入口点写法彻底失效 |
| 1.88 (2025-06) | `#[unsafe(naked)]` + `naked_asm!` 稳定 | 自己写入口点不再需要 `global_asm!` |
| 1.95 (2026-04) | 自定义 target JSON 需要 `-Z unstable-options` | 官方目标不受影响 |
| 1.98 (2026-09) | 不允许在 Rust 里定义 `memcmp` / `memset` 等 runtime 符号 | 裸机代码旧写法失效 |
